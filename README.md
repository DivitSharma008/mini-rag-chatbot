# 📄 Mini RAG Chatbot

Ask questions about any PDF and get grounded, source-cited answers — powered by retrieval-augmented generation (RAG).

Upload a document, and the chatbot retrieves the most relevant passages and uses them (and only them) to answer your questions, showing exactly which chunks of the document it used.

App Link: https://divitsharma008-mini-rag-chatbot-app-ydhaxp.streamlit.app/
---

## Features

- 📤 Upload any PDF — no pre-processing required
- 🔍 Semantic search over document chunks using FAISS
- 🤖 Answers generated by Google's Gemini API, grounded strictly in retrieved context
- 📚 Source citations — see exactly which chunks/pages an answer came from
- 🚫 Honest about limits — says "I don't know" instead of hallucinating when the answer isn't in the document
- ⚡ Runs entirely in-memory per session — nothing persists between users

## How it works

```
PDF Upload
    │
    ▼
Text Extraction (PyPDFLoader)
    │
    ▼
Chunking (RecursiveCharacterTextSplitter)
    │
    ▼
Embedding (HuggingFace all-MiniLM-L6-v2)
    │
    ▼
Vector Index (FAISS)
    │
    ▼
Similarity Search  ──►  Top-k Relevant Chunks
    │
    ▼
Gemini LLM (answers using retrieved chunks only)
    │
    ▼
Answer + Source Citations
```

1. **Ingest** — the uploaded PDF is parsed into page-level text
2. **Chunk** — text is split into overlapping ~1000-character segments, so no idea gets cut off at a boundary
3. **Embed** — each chunk is converted into a vector (a numeric representation of its meaning) using a local HuggingFace model
4. **Index** — vectors are stored in a FAISS index for fast similarity search
5. **Retrieve** — when you ask a question, the top-k most semantically similar chunks are pulled from the index
6. **Generate** — those chunks are passed to Gemini along with your question, with explicit instructions to answer only from the given context

## Tech Stack

| Layer | Tool |
|---|---|
| Orchestration | [LangChain](https://python.langchain.com/) |
| Vector search | [FAISS](https://github.com/facebookresearch/faiss) |
| Embeddings | [Sentence-Transformers](https://www.sbert.net/) (`all-MiniLM-L6-v2`) |
| LLM | [Google Gemini API](https://ai.google.dev/) (free tier) |
| UI & deployment | [Streamlit](https://streamlit.io/) |

## Getting Started

### Prerequisites
- Python 3.10+
- A free [Gemini API key](https://aistudio.google.com/)

### Installation

```bash
git clone https://github.com/<your-username>/mini-rag-chatbot.git
cd mini-rag-chatbot

python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

pip install -r requirements.txt
```

### Configuration

Create `.streamlit/secrets.toml` in the project root:

```toml
GOOGLE_API_KEY = "your_key_here"
```

> This file is gitignored — never commit real API keys.

### Run locally

```bash
streamlit run app.py
```

Open the local URL Streamlit prints, upload a PDF, and start asking questions.

## Design Decisions & Tradeoffs

- **User-uploaded PDFs over a fixed document** — makes the demo more general-purpose and interactive, at the cost of not persisting an index between sessions (each upload builds a fresh in-memory index).
- **HuggingFace embeddings (local) + Gemini (hosted API)** — avoids needing a paid OpenAI key, while keeping embedding computation free and local.
- **Explicit "say I don't know" prompting** — retrieval alone doesn't prevent hallucination; the prompt template explicitly instructs the model to stay within the provided context.
- **10MB upload limit** — protects app performance and free-tier API quota from oversized documents.

## Known Limitations

- Free-tier Gemini API quota is limited (20 requests per period on `gemini-2.5-flash`) — heavy use may hit rate limits
- Very short or sparse documents can produce less coherent answers to broad, vague questions (e.g. "what is this about?") — retrieval works best with specific queries
- No persistent chat history across sessions or page reloads
- No OCR — scanned/image-only PDFs won't extract text

## Possible Extensions

- Support multiple PDFs in one session (a small knowledge base instead of a single document)
- Add conversation memory for follow-up questions
- Swap FAISS for a persistent vector DB (e.g. Chroma, Pinecone) if moving beyond a single-session demo
- Let users choose chunk size / retrieval `k` from the UI
